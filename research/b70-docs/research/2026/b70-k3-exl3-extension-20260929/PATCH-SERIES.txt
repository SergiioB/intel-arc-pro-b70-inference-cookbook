D2, build integrity: build_ext.sh:18 ends compiler pipeline in '|| true'. A failed compile with an older _C.so present can succeed at the final ls. Separate fail-closed build-script patch removes the swallowing pipeline. Not a GPU-kernel bug.

No synchronization occurs on the default non-LUT K3 device launch path, but a literal 'no dynamic allocation in captured region' claim is NOT statically true of this upstream API. Graph-private allocator behavior requires later trace/replay proof; strict zero-allocation compliance remains HOLD pending architect acceptance of graph-private pre-reserved allocation or a separately scoped caller-owned workspace API. No unsafe process-global scratch cache is introduced to conceal this issue.
D4, numerical semantics: exact trellis reconstruction and one-hot decode are distinct from dense linear bit identity. GemvKernel uses per-tile fp16 hacc (:492/:552-555); DPAS is fp16 operands/fp32 accumulate (:829-830); Triton uses fp32 dot/atomic split reduction (triton_kernels.py:173-175). Dense random output equality is not promised. Exact decode gates remain zero-tolerance; dense comparison uses a predeclared tolerance and is not called bit-exact.
