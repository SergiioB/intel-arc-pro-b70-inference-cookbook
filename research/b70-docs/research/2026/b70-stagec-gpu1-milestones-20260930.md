## 4. C1 executable milestone — split-parallel fp32 reduction + unchanged FWHT

**Hypothesis:** sequential reads of P fp32 partials in one ESIMD thread underutilize reduction bandwidth; a two-stage split-parallel reduction can repay one extra graph launch for high-P down_proj. This is a new reduction structure, not resurrecting the existing slower last-arriver fusion (`.../src/csrc/exl3_ops.sycl:227-281`).

Source: `.../src/csrc/exl3_esimd.h:318-337` sequentially adds `[P,M,N]` in one `simd<float,128>` before FWHT; `.../src/csrc/exl3_ops.sycl:50-58,318-345` sizes/allocates partials and dispatches final reduction.

Single variant **C1-R4**:

1. Preserve GEMM, had_in, fp32 partial storage and codebook decode unchanged.
2. Stage 1 work item `(group_p,m,nb)` reads **four consecutive p slices**, accumulates in fp32 in fixed ascending order, writes `[ceil(P/4),M,N]` fp32 grouped sums. Tail p masked; complete output write every invocation; no atomics/counters.
3. Stage 2 reads grouped sums in fixed ascending order, calls the unchanged `fwht128`, normalization, svh and final output cast. P=1 uses incumbent (no added stage); host dispatch frozen before capture. No fp16/bf16 partial narrowing in initial variant.
4. New workspace exactly `ceil(P/4)*M*N*4` bytes, graph-private and owned through replay/destruction. No process-global scratch cache. Grouping reorders fp32 arithmetic: **not lossless by construction** and not automatically permitted by the K3 1-ulp result. Independent numerical and task gates below apply.

Initial down geometry M=4, Kdim=17408, N=5120, actual P computed with identical incumbent MB4/NT4/split policy. Separately benchmark had_out on **identical fully initialized fp32 partials**; do not use the debug skip-GEMV build's unwritten scratch as correctness input. Then whole public linear operation on real read-only tensors. Reproduce gate_up and mixed-head controls only after down passes; preserve unchanged P=1 head.

Cheap falsifier **before expensive integration**, ≤15 min CPU work: derive actual P from source policy, stage launch count/bytes/work-item census and compile just the two reduction kernels offline. If the candidate cannot expose split parallelism (P≤4), adds excessive register spills, or stage-1+stage-2 cannot plausibly beat a 14 µs-class historical stage, stop C1. After GPU authorization, first ≤10-min down-only paired screen is the decisive cost falsifier: baseline/candidate graph replay, two reversed orders, same GPU1 cap. Require **≥15% down reduction-latency decrease in both orders** AND **no whole-op regression >2%**. Fail → no all-family build or serving integration, preserve negative result and advance C2.

C1 deliverable at 80 min: owned source/library/native ISA + numerical/D3 logs + same-session paired down result, either qualified candidate or honest falsification. Broad-family promotion requires measured weighted reduction saving **≥0.35 ms/pass**, no >2% guard-family regressions, and retained full-op control. Price saving using actual module call census; never imply the whole 1.4–2.1 ms is removed. Reduced-precision partials are a separately authorized later candidate with independent error budget, not a silent C1 fallback.

## 5. C2 executable milestone — K-paired four-row DPAS operand pipeline

**Hypothesis:** serial per-strip reconstruction/B-operand reuse exposes decode–DPAS dependency bubbles at M4; pipelining two K tiles with two distinct B operands improves issue overlap without changing NT/MB or P. This is a genuine per-strip-work rewrite, not forced-vector M4 or NT/MB sweeping.

First **one variant, one family**: down_proj, real K4/cb2, M=4, Kdim=17408 → N=5120. Freeze MB4, NT4, local=8 and exact incumbent split policy. Do not also change qkv in initial pilot. Source `.../src/csrc/exl3_esimd.h:593-627,790-857` decodes each tile then issues `xmx::dpas<8,4,float,float,fp16,fp16>`; `.../src/csrc/exl3_ops.sycl:98-128,138-145,318-326` binds launch and P. Existing `EXL3_BV_ALL` comments at header:799-812 describe across-j operand independence; **simply enabling that old flag is not this milestone**.

Single variant **C2-KPAIR**:

- Replace the row-tile loop for this exact specialization with an explicit two-K-tile pipeline: prepare trellis words/activation for r and r+1, decode j into distinct B0/B1, issue DPAS for r then r+1 to the same per-j fp32 accumulator; reuse each B bank only after its dependency is complete. Generate/inspect scheduling to see whether overlap survives compiler lowering.
- Keep each accumulator's K order and codebook fp16 decode unchanged; no affine fold, no fake A/B flags, no split/partial cast, no altered Hadamard. Handle odd `rows_per_split`/final split via guarded one-tile epilogue; never read the next shard or past packed storage. Reconstruct weights once per tile, not four scalar GEMVs.
- Retain fp32 `[P,M,N]` and incumbent had_out. C1 not combined for the first result: isolates main-kernel gain. Public op interface unchanged; specialized fallback to incumbent for every untested M/K/cb/geometry.

Cheap falsifier ≤20 min: minimal specialization offline native build, static packed-address/odd-tail proof, before complete library/integration. Require actual alternating independent B-bank operations/overlap in ISA, correct DPAS depth **8**, repeat **4**, execution width **16 outputs**, fp16 operands/fp32 accumulator. If compiler serializes the same dependency chain or spills the live B banks, stop rather than spend the remaining hours. Compiler scheduling alone is not proof of speed.

After GPU authorization first down-only paired screen ≤15 min: exact controls and quality before timing. Gate **≥8% whole-linear graph-replay latency gain in each reversed ordering**, bulk cross-check same direction, no deterministic/numerical/capture violation. Within ±5% historical drift or disagreement of orderings → no robust win. Fail → record failure and finish this bounded milestone; no NT/MB rescue sweep. Pass → next allocation may port exactly this structure to qkv-class 5120→12288, not a second speculative variant. Require a measured weighted M4 pass saving ≥5% on fresh GPU1 family census before serving integration; do not extrapolate a down-only success to all 400 modules.
