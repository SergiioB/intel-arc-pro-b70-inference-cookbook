# Format review — ranked table and kill conditions

**Screen E8; do not assume it wins.** Scalar shaping plausibly contributes to R4's 2.9× KL gap, but causality is unsettled. The decisive control is now **`int4_g64_rht` versus `e8rvq4_rht`**, with identical two-sided transforms, calibration, validated Hessians and evaluation. Probabilities below are **[UNVERIFIED] subjective priors**; products are ranking scores, not calibrated joint probabilities. Quality = final-logit KL ≤EXL3-4 at ≤4.25 **body** bpw, metadata included. Speed = ≥1.30× **route** decode at unchanged accepted-token yield.

**Price:** `gain=1/(1-f+f/k)`. At f=.75 [UNVERIFIED], 1.30× route requires k=1.444×: **550.3 GB/s at 4bpw**, **551.2 at E8's 4.00625bpw** (K5120), **584.7 at 4.25bpw**. The weaker kernel-only bar is **495.3 GB/s**. At 5.125bpw requirements become **705.1/634.6 GB/s**, above 608 GB/s pin. Count fixed heads, wraps/drafting and padding separately. B_FAKE's 636 *logical-byte* GB/s is not physical throughput or an attainable serving guarantee (RL-119).

**QTIP instruction price [UNVERIFIED]:** HYB needs roughly **4–7 scalar lane-ops per pair** (hash, index shift/mask, sign/XOR), plus one dword SLM lookup. At 4bpw, 512 B =1024 weights: ideal SIMD8 normalization gives **256–448 ALU issue-equivalents/512 B**, excluding trellis extraction/scales/DPAS moves and gather sends. Actual width, modifiers and packing may change this substantially. EXL3's retained census is **~336 total, ~330 ALU/moves/512 B** (`research/2026/b70-kernel-forensics-next-20260930.md:169–177`). Thus HYB is **not yet proven cheaper**. A same-issue-rate 1.444× target needs roughly **≤233 total equivalent instructions/512 B**; only emitted matched-tile ISA can price it. Pure LUT removes hashing, trading issue work for SLM traffic/conflicts. CUDA “2 instructions/weight” is not an Xe2 count.

Open-source quantizer: [QTIP pinned tree](https://github.com/Cornell-RelaxML/qtip/tree/e90c6688c8dfae326a3a81b5eb032db7c6680ec0), `lib/codebook/bitshift.py`, `lib/algo/finetune.py`, `quantize_llama/quantize_finetune_llama.py`; HYB flags `--K 4 --L 16 --V 2 --decode_mode quantlut_sym --tlut_bits 9`. ## Kill conditions — cheapest first

1. **Reject the causal overclaim.** R4 writers rotate only outputs: down/o input Hessians stay unrotated (`scripts/tmp/r4_r0_20261011.py:598–617`). GPTQ uses min/max scales, no clipping search (`:212–225`), static order and arm-specific calibration (`:229–287,1049–1106`). G64 improves G128 KL **14.1%**, proving recipe sensitivity. Fold-only BF16 KL **.00013** versus R4 .00353 is smaller, but not subtractable. EXL3 calibration mismatch, desc_act-off and outlier sensitivity remain material possibilities. Gaussian asymptotic unweighted RD is not logit KL; side-scales/GPTQ feedback break direct identification of “2.95× MSE ⇒ 2.9× KL.” Use the two-sided scalar control, then one matched clipping/order diagnostic if attribution matters. Never use hidden-channel-softmax KL (RL-161).
2. **Block on codec/Hessian defects.** Exhaustive 65,536-code decode parity; sampled exact-NN oracle including signs/parity/ties; W_hat reconstructed with **stored FP16 scales**. Require SPD/finite factors plus residual against damped H, bounded RAM and unchanged damping. Failure is harness-blocked, not format failure (RL-168/169). Gaussian/real-tensor MSE and H-weighted error detect broken encoding, but cannot alone certify or refute model KL.
3. **Kill this E8 recipe at the matched 13-layer prefix** if KL **>1.10× EXL3** after the single predeclared correction. Failed sanity instead blocks scoring. The 1.10 allowance only advances; final goal remains ≤1.00×. Preserve per-position KL/canary margins. Old plain-GPTQ prefix margin stayed positive: it did **not** reproduce the full-model “30” defect (`smokeL11.out:74–81`). **No kernel GPU work before explicit “E8 GPU GO.”**
4. **Kill speed at compile pricing, then authorized paired measurement.** Actual ISA/SLM/GRF must price ≥1.30× route. Measure correct fused M4 on weighted qkv/gate-up/down shapes with >L2 ring, wraps and reductions—not standalone lookup or fourfold-counted rereads. Need ~551 GB/s under f=.75; measure f. Table fit does not prove conflict-free throughput. HQ4's ~24 GB/s history (RL-145) refutes “simple decoder ⇒ fast kernel.”
5. **Kill adoption on full-model/route failure.** Prefix success cannot certify late layers, long context, canaries, capture or MTP yield. Require full KL ≤EXL3, same battery pass set, ≥1.30× paired decode at both prompt lengths. QuIP# fine-tuning gains do not transfer to no-FT scratch code.
