## What V6 changed (diff vs `SC_5.00bpw_H6` @ dfe2f4fd)

- `config.json`: embedded `quantization_config` gains `"vision_bits": 6`
  (line 151-152; `mtp_bits: 4` etc. unchanged). `language_model_only: false`.
- `quantization_config.json` (629,067 B): **byte-identical** — same
  `tensor_storage` K map, `bits 5.0 / head_bits 6 / mtp_bits 4 / codebook mul1 /
  out_scales always / version 1.4.2`, zero `model.visual.*` entries.
- `cal_trace.safetensors` LFS oid identical (`a034bee4…`) → same calibration.
- Weight index: `model.visual` 333 tensors → 987. In H6 the whole 27-block ViT
  is fp16 `.weight`/`.bias`. In V6 every visual linear (`attn.q/k/v_proj`,
  `attn.proj`, `mlp.linear_fc1/2`, `merger.linear_fc1/2`) is EXL3 **K=6 mul1**
  (trellis third dim 96), **plus** fused fp16 `attn.qkv.weight` is still kept
  (backward-compat for fused-only loaders; V6 stores both formats for qkv).
- LM/MTP trellis payloads are **bit-identical**: sha256 of
  `layers.0.linear_attn.{in_proj_qkv,in_proj_z,out_proj}.trellis` equal in both
  checkpoints (sampled full tensors). V6 is a repack, not a re-quant of the LM.

## exl3xpu-mixedk:20261013 compat

Kernel side (`b70/serve/patches/0001-exl3-ops-mixed-k.patch`): mul1 cb=2 for
K = 2..7 — every V6 K (LM 4-7, visual 6, mtp 4, head 6) is in range; no mcg,
no packed su/sv tensors anywhere in V6. `LinearEXL3` bias is supported in the
exllamav3 loader (`linear.py:436-455`); vLLM plugin `apply` adds `bias`
(`vllm_plugin.py:356-357`) and all V6 visual dims are 128-aligned
(1152/3456/4352/4608/5120).

Blocker is in `vllm_plugin.py`:

- `_bits_for` returns `None` for any prefix containing `"visual"` /
  `"vision_tower"` → every vision linear gets `UnquantizedLinearMethod` and
  vLLM looks for `<mod>.weight`. V6 has **no** `.weight` for `attn.proj`,
  `mlp.linear_fc1/2`, `merger.linear_fc1/2` (trellis-only) → uninitialized
  params → hard load failure. (`attn.qkv.weight` fp16 *is* present and would
  load; the redundant `q/k/v_proj.*` splits are ignored checkpoint keys.)
- `model.yaml` for the recipe sets `limit_mm_per_prompt {image:32,video:4}` —
  the vision tower is instantiated at serve time; this is not a dead path.
- A patch that just drops the visual bypass is **insufficient**:
  `_norm_key` (`vllm_plugin.py:36-46`) collapses `model.visual.blocks.N.*`
  to the leaf name (`proj`, `linear_fc1`, …), colliding all 27 blocks into one
  storage key, and `maybe_update_config` (`:94-116`) would then record the
  wrong default K (`int(bits)`=5 vs actual 6). Needed: keep `visual.blocks.N`
  in normalized keys, default visual members to `vision_bits` (config.json
  already carries it), and either keep `qkv` unquantized (fp16 `.weight` is
  shipped) or add a `FUSED["qkv"]=[q_proj,k_proj,v_proj]` member map — the
  mixed-K run machinery handles either.

**Verdict: NEEDS A PATCH** — `vllm_plugin.py` visual-quant path
(norm-key fix + vision_bits default + `_bits_for` bypass removal). Language
model serving is byte-for-byte identical to the H6 we already serve, so V6
offers nothing for text until vision quant is enabled; then it saves ~440 MB
of weights vs H6's fp16 tower.
