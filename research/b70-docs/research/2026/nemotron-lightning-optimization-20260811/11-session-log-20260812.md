# Nemotron vLLM decode optimization — full session log (2026-08-12)

Author: B70 inference host research session. Companion to `10-vllm-gptq-readiness-20260812.md`.
Purpose: chronological, evidence-linked record of the entire 2026-08-12 push to find why
Nemotron-3.5-Lightning vLLM decode was weak (~21.8 t/s) and raise it toward/above the

## 1. Hugging Face survey + MTP-head discovery

- Searched HF for a better ready artifact: no ready B70-compatible INT4 target beat the
  local GPTQ (Unsloth's "new" repo is a 63 GB BF16 mirror; official repos are BF16/NVFP4).
- **Discovery**: the official BF16 (`nvidia/NVIDIA-Nemotron-3.5-Lightning-30B-A3B-BF16`)
  carries a real MTP head — 270 tensors (`mtp.layers.0` attention + `mtp.layers.1` MoE with
  gate/shared_experts/128 routed experts/e_score_correction_bias) all in
  `model-00014-of-00014.safetensors` (2,670,685,240 B, sha256 64577b275ca4...). Config:
  `num_nextn_predict_layers: 1`, `mtp_layers_block_type: ['attention','moe']`,
  `mtp_hybrid_override_pattern: None` → defaults to `"*E"`.
- The nightly ships native NemotronH MTP machinery: `nemotron_h_mtp.py`
  (`NemotronHMTP`/`NemotronHMultiTokenPredictor`), registry `NemotronHMTPModel`,
  `hf_config_override` auto-maps `nemotron_h` + `num_nextn_predict_layers>0` → draft,
  V1 `MTPSpeculator` (`{"method":"mtp"}`), embeddings/lm_head shared from the target.
- The local GPTQ artifact's config ALREADY declared `num_nextn_predict_layers: 1` — the
  loader expected a head the conversion had dropped.

## 2. MTP-head conversion (b70-nemotron-mtp-head-gptq.py)

- Downloaded shard 14 (aria2c CDN method, ~86 MB/s). Converted the 270 mtp.* tensors with
  the exact backbone contract (GPTQ INT4, sym, G64, signed+8 low-first nibbles, BF16
  scales, zero qzeros, arange g_idx; 1D norms passthrough BF16). Output
  `nemotron-lightning-gptq-sym64-mtp-20260812/` (symlinked base + `mtp-00001.safetensors`
  722 MB, 1062 tensors, merged index 25,317). Quantization stats: zero clipped, max abs
  error 0.21, mean 1.3e-3.
- **Incident (data integrity)**: the script symlinked the base index then wrote the merged
  index through the symlink — corrupting the base artifact's index (mtp entries + missing
  shard reference). Restored the base index (24,255 tensors / 36 shards / 0 mtp) and made
  the MTP dir index a real file. Script now excludes overwritten files from symlinking and
  refuses to write through a symlink. Lesson recorded in AGENTS.md §15.11.
- **No-spec control PASSES**: the MTP artifact serves without `--speculative-config`
  (0 assertions, init 263 s). The shard is benign (base skips `mtp.` via skip_prefixes).

## 3. Native MTP attempts (result: blocked by upstream XPU routing bug)

- `{"method":"mtp","num_speculative_tokens":2}` crashed at engine-init warmup:
  `Assertion 'index out of bounds: 0 <= tmp0 < 128'` (528 lanes) in an Inductor kernel.
  Retained the kernel (`/mnt/<models-disk>/inductor-cache/vv/cvvhmtiqivc2c3jhlx4gwpbq6t4ril6e3gfhpncu4bpm6lbbxu76.py`):
  the grouped-topk router's score gather (source nodes `[group_scores]`,
  `[scores, topk_weights, sum_2, topk_weights_1]`).
- Root cause: `grouped_topk_router.py` line 75 has an UNCONDITIONAL `@torch.compile` on
  `grouped_topk`; the DRAFT's MoE falls back to the torch routing path (XPU WNA16 backend
  is modular — `XPUExpertsWNA16.is_monolithic()==False`), and the compiled gather reads
  out-of-range expert ids on XPU. The BASE never executes it (fused native routing).
- Fix attempts that failed: keep/force quant_config on the draft (two patches) — the
  server imports vLLM from `/workspace/vllm`, NOT site-packages (found by the specialist),
  and the active draft path is `MTPSpeculator.load_draft_model → load_eagle_model`.
- **CPU-routing workaround** (`patch_xpu_grouped_topk_cpu.py`): grouped routing on CPU,
  decorator bypassed on XPU → MTP passes engine init (first time, 0 assertions).
- **MTP screen = LOSS**: 19.61/19.56 t/s (−10% vs no-spec), 0/110 draft acceptance,
  temp-0 nondeterminism. The converted head loads but its logits are uncorrelated
  (likely the heterogeneous puzzle-expert MTP MoE through XPUExpertsWNA16). Not a candidate.
- **N-gram diagnostic**: engine init passes (crash is draft-specific) but output is
  non-deterministic at temp 0 and unstable across runs — not a candidate either.

## 5. THE ROOT CAUSE of the weak decode (profile-driven)

- XPU torch profile of 32 generated tokens: **30,409 kernel launches (~950/token)**,
  **32.2 ms/token CPU time in urEnqueueKernelLaunchWithArgsExp**, only **9.45 ms/token**
  actual GPU kernel time. Evidence: `results/2026/08/nemotron-gptq-builtin-profile-20260812T171658Z-671822/`.
- SSU was NOT the bottleneck (0.36 ms/token). Dominant device work: MoE grouped GEMM
  (80-83 ms), INT4 W4A16 GEMM (61.7 ms), router topk (32.8 ms).
- The architect's bandwidth model: active weights ~1.45-1.6 GB/token → ideal 2.4-2.7
  ms/token (~370+ t/s) at 608 GB/s. Observed 46 ms/token = ~5% effective bandwidth.
- Interim best safe config (compiled, graphs OFF, async, SSU B8/W4): 23.05/23.12 t/s.
  230 W A/B: flat (23.55 vs 23.50; draw ~89-90 W) — not a power lever.

## 6. XPU graph breakthrough (the fix)

- **v1** (`patch_xpu_grouped_topk_native.py`): native XPU grouped-topk replacement
  (repeated argmax + one-hot masks; matches the reference topk(2).sum() formula) — device
  native, no CPU sync → PIECEWISE + FULL decode graphs capture. Measured 93.17/87.37 t/s
  (n=3). BUT deterministic replay FAILED (also without graphs).
- **Isolation** (decisive): full-eager + native router IS deterministic (3 identical
  temp-0/seed calls byte-identical) → the router math is exonerated. Sampler-eager and
  no-async didn't help. The nondeterminism is the compiled/graph KERNEL execution itself
  (XPU torch.compile/triton FP race at contested near-tie logits; occasionally early
  divergence). Same bug class as vLLM's own PowerPC-argmax compile note.
- **v2** (`patch_xpu_grouped_topk_native_v2.py`): adds `torch.compiler.disable` on XPU
  (graph break at the router). Graphs still capture; determinism still fails (compiled
  kernels race elsewhere).
- **Final measured config**: compiled + PIECEWISE/FULL XPU graphs + native router v2 +
  `--async-scheduling` + SSU B8/W4 (config at `scripts/tmp/ssu-b70-b8w4/`).
  **n=5: p512/g128 93.00 t/s (92.96-93.03), p8192/g128 87.25 t/s (87.22-87.31)** —
  4.27×/4.01× over the eager baseline, above the 78 t/s reference. Evidence:
  `results/2026/08/nemotron-gptq-graph-n5-20260812T2045Z/` (n5-summary.json, manifest, raw SSE).
- Coherence verified on all 6 measured reps: structured, on-topic, exact 128 tokens,
  100% printable.
- **Remaining blocker (A-grade gap)**: deterministic replay (temp-0 byte-identical) does
  not hold on the compiled/graph path — XPU compiled-kernel FP race. Specialist in flight.
