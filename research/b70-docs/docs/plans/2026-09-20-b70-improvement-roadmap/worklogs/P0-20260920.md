## Probe batch — results

### Probe: K216 routed-operator identity and cost (highest-value P0 item)

**Source confirmation (pinned tree, `~/llama.cpp` @ `1692f9e50` + local diff).**

- `ggml_sycl_mul_mat_id()` (`ggml/src/ggml-sycl/ggml-sycl.cpp:4770`) tries
  `ggml_sycl_mul_mat_id_mmvq_fused()` when `ne12 == 1` (single token) and otherwise falls
  through to `stream->memcpy(ids_host, ids_dev, …)` + **`stream->wait()`** (a full device
  sync) + a host-side per-expert loop.
- The fused path (`ggml-sycl.cpp:4669`) accepts only `src1`/`dst` F32, contiguous `src1`,
  `ids->ne[1] == 1`, `ne11 ∈ {1, n_ids_per_group}`; it then calls
  `ggml_sycl_mul_mat_vec_q_id()` (`mmvq.cpp:2569`) with **device-resident `ids_dev`**.
- **The local diff (uncommitted, written 2026-08-26) adds `case GGML_TYPE_IQ3_XXS` and
  `case GGML_TYPE_IQ3_S` to that switch** (`mmvq.cpp:2648`, `:2673`), each reading
  `ids_dev[expert_idx]` on device. This is exactly the P1 repair, already implemented in
  the working tree — **built but never parity-tested or measured** (its own note,
  `research/2026/dsv4-k216-buun-moe-cache-20260825.md`, says "Smoke not run 2026-08-26").
- **Graph-capture cause identified:** `check_graph_compatibility()` disables SYCL graphs
  for `GGML_OP_MUL_MAT_ID` *because* of that host wait (`ggml-sycl.cpp:5687-5692`), and
  separately for `device_count > 1`. So the host wait blocks graph capture independently of
  the dual-card rule — P1's repair is a prerequisite for capture, not a parallel lever.
